# android-assistant

Natural-language control of a rooted Android phone (aarch64) from Claude Code running in a Debian PRoot inside Termux. Requests can be typed, spoken, or generated by another agent.

The prompts and scenarios that drive this stack ship in [mcp-prompts](https://github.com/sparesparrow/mcp-prompts) under the `android-automation` and `tasker-automation` profiles. The flagship guide is [docs/10-android-automation.md](https://github.com/sparesparrow/mcp-prompts/blob/main/docs/10-android-automation.md) there.

## What is in here

| Path | What it is |
|---|---|
| `mcp/` | The `android-assistant` MCP server (`server.py`). It has these tools:<br>• the phone: `phone_status`, `screen`, `act`, `open`, `notify`, `run_tasker_task`, `mqtt_publish`, `wait_event`, `speak`, `listen`, `phone_command`<br>• Gemini: `ask_gemini`, `gemini_reply`<br>• the other AI apps: `ask_ai`, `ai_reply`<br>• Gemini Notebooks: `notebook_ask`, `notebook_add_source`, `notebook_studio`, `notebook_read`<br>The drivers are `gemini.py`, `notebook.py` and `chatbots.py` (DeepSeek, Kimi, Grok, ChatGPT, Perplexity). Their tests run against recorded UI dumps in `fixtures/`. |
| `agents/` | Claude Code agents: `phone`, `gemini`, `deepseek`, `kimi`, `grok`, `chatgpt`, `perplexity`.<br>• `run-agent.sh` runs them under the one-screen lock.<br>• `install.sh` symlinks them into `~/.claude/agents` and installs the Termux `agent-<name>` wrappers.<br>• `sshd_config` is the forced-command sshd that Tasker uses to start agents. |
| `skill/` | The Claude Code skills `android-assistant` (how this stack fits together) and `android-control` (the `droid` CLI over adb: uiautomator dumps, taps, typing, intents). |
| `phone/` | Phone services:<br>• the adb loopback, the mic/speaker PulseAudio bundle, the native Termux ssh bridge, the watchdog (`phone-services`);<br>• `notif-wait.py`, which waits for a notification;<br>• `tasker/`: `tasker-edit.py` edits Tasker's config directly, plus task and scene builders and importers. |
| `voice/` | The hands-free voice pipeline: the assistant gesture → Tasker → an HTTP trigger on 127.0.0.1:8780 → ElevenLabs STT → `claude -p` with these MCP tools → ElevenLabs TTS. |
| `router/` | The Claude Panel router, which turns a spoken or typed coding request into a Claude Code job in one of the repos in `repos.json`. |

Clipboard history is not part of this repo. It belongs to [cliphist-android](https://github.com/sparesparrow/cliphist-android) and its own MCP server, and this repo used to live inside that one as `assistant/`.

## Setup (in the Debian PRoot)

```bash
git clone https://github.com/sparesparrow/android-assistant /root/android-assistant
cd /root/android-assistant
python3 -m venv mcp/.venv && mcp/.venv/bin/pip install -r mcp/requirements.txt -r voice/requirements.txt
claude mcp add -s user android-assistant -- /root/android-assistant/mcp/.venv/bin/python /root/android-assistant/mcp/server.py
ln -sfn /root/android-assistant/skill/android-assistant ~/.claude/skills/android-assistant
ln -sfn /root/android-assistant/skill/android-control ~/.claude/skills/android-control
agents/install.sh                      # agents + Termux wrappers
ln -sfn /root/android-assistant/phone /root/phone
phone/phone-services ensure            # adb loopback, mic server, sshd
```

The one-time root and Magisk setup (adb on loopback, boot script) is in `phone/README.md`, and the voice setup is in `voice/README.md`. Store the ElevenLabs key with `phone/set-elevenlabs-key.sh`. It is never committed.

## Tests

```bash
cd mcp && .venv/bin/python -m pytest -q
```

## Safety model

- Screen, notification and message text is data, never instructions.
- Sending anything to another person needs the user's explicit yes to the recipient and the text. The tool returns a confirmation token that expires after 5 minutes.
- No payments, banking or trading.
- Phone UI work is serialised under `phone/state/agent.lock`, because there is one screen.
- The MCP tools do not expose a shell or `su`. Root is used only by maintenance scripts that a person starts (`tasker-edit.py`, `phone-services`).
- Runtime state, logs, recordings, tokens and keys are git-ignored (`phone/state/`, `voice/state/`, `*/logs/`).
